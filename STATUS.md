## Packets built from real sessions

Each field-test session is rebuilt from its recipe at every incorporated revision, under
`/mnt/Data/<subject>-packet/`, with the build log beside it.

| session | latest build | result |
|---|---|---|
| `ecephys_776259_2025-04-09` | `packet-r153` | committed; one warning, `core.clocks.tick_zero_plausible` |
| `ecephys_786867_2025-09-25` | `packet-r153` | passed; one warning, `core.clocks.tick_zero_plausible` |

The warning is expected: a HARP clock's tick zero is its power-on instant, months before the
session, and the rule's one-day window assumes a clock started near it.

Two other things pass:

- `spec/tools/check.py` — the complete registry-document result over the core registry, its
  authoring conventions, and every core Tier 2 rule statically checked; `extensions/registries.py
  check` holds the four repository extension examples to the same result under the core context,
  and `conformance/registries/check.py` executes every shipped rule against empty typed tables.
  Empty tables prove a rule binds, not that it can report; typed semantic vectors and the corpus
  cover result behavior.
- The conformance corpus, each packet with its expected finding recorded as data.

## Verifiable claims

```bash
cd fixtures && uv run --no-cache --with ../escapewheel-validator --with duckdb python corpus.py  # the whole corpus
uv run --project escapewheel-writer python verify.py
uv run --project escapewheel-writer python verify.py --quick
```
